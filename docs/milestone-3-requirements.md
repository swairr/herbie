# 里程碑三 需求方案

目标：日志 / 手账 —— 记录会议纪要、每日思考等自由文本，按本地自然日组织，手动导出 markdown，供外部 AI 归纳总结。

平台：Windows（同前）。领域术语见根目录 `CONTEXT.md`；架构决策见 `docs/adr/`。

## 1. Journal Entry（日志条目）

- **统一概念**：会议纪要、每日思考不单独建模，统一为 Journal Entry；区分靠正文中的 `#tag`（如 `#会议`），复用 Label 机制，不设类型字段。
- 字段：`id`、`title`（**可选**）、`body`（必填，多行）、`date`（归属日，本地自然日，天粒度 —— 见 ADR 0003）、`createdAt`、`updatedAt`、`deletedAt`。
- 归属日默认今天；可补记（选过去日期），可事后改期。
- 一个自然日 0..n 条，同日多条按创建先后排序。
- 标题 / 正文创建后随时可编辑；删除为软删除（`deletedAt`），UI 默认不展示。
- 与 Todo / Activity Segment **无结构化关联**（无外键）；关联通过 `#tag` 语义化表达。

## 2. 「日志」页签

- 主界面第三个页签，与「待办」「时间」并列；默认显示今天，可切换日期查看历史（复用「时间」页签的日导航模式）。
- 当日条目列表按创建先后排列；无标题条目以正文首行摘要展示。
- 创建 / 编辑：`title` 可选、`body` 必填（空正文不允许提交）、归属日可选择（默认今天）。
- 保存时重新解析 Label、更新 `updatedAt`。

## 3. Label 宇宙扩展

- Journal Entry 正文中的 `#tag` 与 Todo `detail` 中的 `#tag` 属于**同一 Label 宇宙**：同名 `#tag` 跨实体视为同一 Label。
- Label 的事实源从「仅 Todo detail」扩展为「Todo detail + Journal Entry 正文」；数据库冗余解析结果相应扩展，保存正文时重新解析。

## 4. Markdown 导出（手动，镜像时间导出）

- 单向导出，sqlite 为唯一事实源（ADR 0001）。
- 复用既有导出目录，新增 `journal/` 子目录，每天一个文件 `journal/YYYY-MM-DD.md`。
- 触发：「日志」页签手动按钮，导出**当前查看日**；同名覆盖，幂等重写（与 `exportTime(day)` 模式一致）。
- 文件内容：当日未删除条目按创建先后排列 —— 标题（无标题则用正文首行）、正文、稳定 id（行尾 HTML 注释，与 `todos.md` 一致，为未来双向同步留路径）。
- **归纳总结在应用外完成**：外部 AI 读取导出目录（git 仓库）进行归纳；本里程碑不做任何应用内总结功能。

## 里程碑三明确不做

- Quick Add 扩展（「存为日志」模式 / 新快捷键）—— 后续独立增量
- 应用内归纳总结（LLM 调用、周报生成、总结视图）
- 日志与 Todo / Activity Segment 的结构化关联（外键）
- 条目的时刻粒度时间戳 —— 天粒度是有意决策（ADR 0003）
- 同日条目的手动排序
- 已删除条目的恢复界面（数据保留即可）
