# 日程以本地自然日为锚点，不建独立日程实体

## 状态

已接受（日程视图重构）。

## 背景

重构要求把待办、活动、日志都关联到日程，并以时间线显示。三类数据已有各自的时间锚点：Todo 的计划时段是本地墙钟（ADR 0005），Activity Segment 的起止时刻是 UTC 瞬时，Journal Entry 的归属日是本地自然日（可选时刻见 ADR 0007）。备选方案是新增 `schedules` 表，让三类实体通过 `scheduleId` 挂到具体日程条目上。

## 决策

「日程」不是持久化实体，而是「某个本地自然日的时间线」。关联是时间上的：条目按其归属日（及可选时刻）落进当天的日程，不引入 `scheduleId` 外键，也不为未安排/未归因的数据制造「无主日程」。

日程视图是日程的主界面，包含计划轨（Planned Slot）、实际轨（Activity Segment）与日志（Journal Entry）；无时刻的待办与日志归入「全天」区。计划与实际只通过显式的 `Activity Segment.todoId` 配对，不按时间重叠自动归因；实际片段在展示层聚合，原始片段可展开。

## 后果

- 不新增日程表；三类实体既有时间锚点继续作为唯一事实源。
- 未安排待办、未归因活动、无时刻日志都有自然归属（全天区 / 实际轨），不存在「挂在哪条日程下」的孤儿问题。
- 若未来需要独立于待办的会议/预约，再引入一等「日程条目」实体，届时取代本决策。
- 计划/实际配对依赖用户显式关联；未归因片段不会被自动算进某个计划，避免「计划写 A、实际做 B」的误判。
