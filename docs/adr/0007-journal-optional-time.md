# 日志条目可选记录本地时刻（部分修订 ADR 0003）

## 状态

已接受（日程视图重构）；部分取代 ADR 0003。

## 背景

ADR 0003 把手账日志定为「一天一页」的天粒度，明确不记录时刻，并预告「未来若要把会议纪要挂回具体时间线，必须做 schema 迁移并补数据」。日程视图重构要求日志与待办、活动一起上时间线；若日志仍只有日期，只能永远停留在「全天」区，会议纪要无法定位到 14:00。备选方案是继续天粒度，或用 `createdAt` 的本地时刻定位——后者把「记录时刻」当成「事件时刻」，补记/改期会错位。

## 决策

`journal_entries` 增加可空 `time`（本地墙钟 `HH:MM`，迁移 0006），不强制填写：

- 有 `time`：日志落在当天时间线的日志窄轨，位置由 `time` 决定；
- 无 `time`：保持天粒度，归入「全天」区；
- `time` 只决定时间线位置，不建立指向 Todo / Activity Segment 的外键。

日志列表与导出按「`time`，否则 `createdAt` 的本地时刻」排序；导出的有 `time` 条目在标题下加 `时间：HH:MM`。

## 后果

- 迁移 0006 只加可空列，无回填；既有日志全部保持无时刻，行为不变。
- 「捕获优先」仍成立：时刻可不填；编辑时清空 `time` 即回到全天区。
- ADR 0003 的「一天一页」心智对无时刻日志继续有效；有时刻日志成为时间线上的定位条目，二者并存。
- 未来若需要时间范围（起止）或日志→待办/活动的显式关联，再单独扩展。
