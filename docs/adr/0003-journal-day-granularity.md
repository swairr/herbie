# 日志条目采用天粒度归属日，而非时间戳

里程碑三的 Journal Entry 以 `date`（本地自然日）作为时间锚点，**不记录具体时刻**。备选方案是 `createdAt` 式时间戳 —— 与应用内其他所有实体（Todo、Activity Segment）一致，表达力严格更高，「某天的日志」可作为派生过滤 —— 但用户明确选择了手账心智：日志是"某一天的一页"，而非事件流中的一个点。天粒度让补记 / 改期的语义自然（选择"哪一天"，而非伪造一个时刻），也让"某天的日志"成为直接的数据归属而非查询过滤。

代价：同日多条之间没有时刻信息，排序只能依赖创建先后（`createdAt` 元数据）；未来若需要时刻粒度（如把会议纪要挂回具体时间线），必须做 schema 迁移并补数据。反转成本高，故记录此决策。
